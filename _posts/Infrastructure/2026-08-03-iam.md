# AWS IAM（Identity and Access Management）の要点まとめ

アクセス管理とセキュリティの要となる **AWS IAM** の重要概念や設計原則について

---

## 1. IAMの基本概念と主要コンポーネント

IAMは、AWSリソースへのアクセスを安全に制御するための機能です。

### 主要なエンティティ

| コンポーネント | 概要・特徴 | ユースケース |
| :--- | :--- | :--- |
| **IAM ユーザー** | 人またはアプリケーションに紐づく個別のアイデンティティ。 | 個別の管理作業、永続的なアクセス情報が必要な場合。 |
| **IAM ユーザーグループ** | 複数のIAMユーザーをまとめて管理するグループ。グループに対してポリシーを設定する。 | 開発チーム、運用チームなど職責ごとの権限管理。 |
| **IAM ロール** | 一時的なセキュリティ情報（トークン）を発行して権限を委任する仕組み。 | EC2からS3へのアクセス、クロスアカウント連携、PassRole。 |
| **IAM ポリシー** | 誰がどのリソースに対してどの操作を許可/拒否するかを定義したJSONドキュメント。 | 権限設定の実体（ユーザー/グループ/ロールにアタッチ）。 |

---

## 2. IAM ポリシーの種類と評価論理

SAA試験では、適切なポリシーの適用と優先順位の理解が問われます。

### ポリシーの種類
1. **アイデンティティベースのポリシー (Identity-based Policies)**
   * IAMユーザー、グループ、ロールにアタッチするポリシー。
2. **リソースベースのポリシー (Resource-based Policies)**
   * S3バケットやSQSキューなど、リソース側に直接アタッチするポリシー（Principalを明示）。
3. **Service Control Policies (SCP)**
   * AWS Organizationsでマルチアカウント全体の利用可能な操作の境界（上限）を定義するポリシー。
4. **Permissions Boundary（権限の境界）**
   * IAMユーザーやロールに設定し、付与できる最大権限を制限する機能。

### ポリシーの評価ルール（明示的な拒否の優先）
AWSポリシー評価の基本ルール：
* **デフォルト拒否 (Implicit Deny)**: 明示的に許可されていない操作はすべて拒否される。
* **明示的な許可 (Explicit Allow)**: 許可（`"Effect": "Allow"`）があればアクセス可能。
* **明示的な拒否 (Explicit Deny)**: **明示的な拒否（`"Effect": "Deny"`）は、すべての許可に優先する。**

---

## 3. IAM ロールの主要なユースケース

試験において最も頻出するパターンです。アクセスキーのハードコードを避け、一時的な資格情報（Security Token Service: STS）を利用することが基本原則となります。

### ① AWS サービスへの権限付与（EC2, Lambda等）
* EC2インスタンスやLambda関数からS3やDynamoDBにアクセスする際、アクセスキーを直接持たせず、**IAMロール（インスタンスプロフィール）を付与**する。

### ② クロスアカウントアクセス (Cross-Account Access)
* 異なるAWSアカウント間のリソースにアクセスする場合、ターゲットアカウント側でIAMロールを作成し、送信元アカウントからの引き受け（`sts:AssumeRole`）を許可する。

### ③ アイデンティティフェデレーション（ID連携）
* 社内のActive Directory（SAML 2.0）やWeb Identity（Cognito, Google, OIDCなど）を利用して、AWS外のユーザーに一時的なアクセス権限を与える。

---

## 4. セキュリティベストプラクティス（試験頻出）

SAAの「信頼できるセキュリティアーキテクチャの設計」分野で重要なポイントです。

* **AWSアカウントのルートユーザーの保護**:
  * 日常的なタスクにはルートユーザーを使用しない。
  * ルートユーザーには必ず**MFA（多要素認証）**を設定する。
  * ルートユーザーのアクセスキーは作成しない（作成済みの場合は削除）。
* **最小権限の原則 (Least Privilege)**:
  * 最初は最小限の許可からスタートし、必要に応じて権限を追加する。
* **アクセスキーの定期的なローテーション**:
  * 永続的なアクセスキーの使用を避け、できる限りIAMロールによる一時的な資格情報を利用する。
* **AWS CloudTrail による監査**:
  * IAMのアクティビティやAPI呼び出し履歴をログとして追跡・監視する。

---

## 5. SAA試験対策・要点チェック

* **AWS STS (Security Token Service)**: IAMロールの引き受けやフェデレーション時に、**一時的なセキュリティ資格情報**（アクセスキー、シークレットキー、セッショントークン）を発行するサービス。
* **`iam:PassRole`**: ユーザーがAWSサービス（EC2やCloudFormationなど）にIAMロールを渡して実行させる権限。
* **IAMのスコープ**: **IAMはグローバルサービス**であり、リージョンごとの設定は不要。
