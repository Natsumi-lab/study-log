# AWS Lambda（サーバーレスコンピューティング）の要点まとめ

サーバーレスのコアサービスである **AWS Lambda** の基本概念や設計パターンについて

---

## 1. AWS Lambdaの基本概要と特徴

AWS Lambdaは、サーバーのプロビジョニングや管理をすることなく、コードを実行できるイベント駆動型の**FaaS（Function as a Service）**です。

### 主な特徴
* **完全マネージド型**: インフラの保守、OSのパッチ適用、自動スケーリングをAWS側が自動処理。
* **従量課金制**: リクエスト数とコードの実行時間（ミリ秒単位）および割り当てメモリ量に応じて課金。
* **イベント駆動型**: S3へのファイルアップロード、DynamoDBの変更トリガー、API Gateway経由のリクエストなどに連動して起動。
* **実行時間制限**: 1回の実行上限は**最大15分（900秒）**。

---

## 2. 実行環境と主要な設定項目

パフォーマンスやコストを最適化するために調整する重要なパラメーターです。

| 設定項目 | 概要・詳細 |
| :--- | :--- |
| **メモリ (Memory)** | 128 MB から 10,240 MB (10 GB) の範囲で設定。**メモリ容量に比例してCPUパワーとネットワーク帯域も自動割り当て**される。 |
| **タイムアウト (Timeout)** | デフォルトは3秒、最大15分。長時間のバッチ処理には向かない（Step FunctionsやECS/Fargateの併用を検討）。 |
| **一時ストレージ (/tmp)** | 関数実行中に一時的にデータを保存できる領域（512 MB〜10,240 MBまで設定可能）。 |
| **Lambda Layer** | 複数のLambda関数で共有できるライブラリ、カスタムランタイム、依存関係のパッケージ。デプロイパッケージのサイズ削減に有効。 |

---

## 3. イベントソースと呼び出しタイプ

SAA試験では「どのサービスがどの呼び出し方式でLambdaを起動するか」がよく問われます。

```
[ 同期呼び出し (Synchronous) ] ──> API Gateway, ALB, SDK ─> レスポンスを即座に返却
[ 非同期呼び出し (Asynchronous) ] ─> S3, SNS, EventBridge ──> リトライ制御 (2回) / DLQ / 宛先 (Destinations)
[ ストリーム系 (Event Source Mapping) ] ─> DynamoDB Stream, Kinesis ─> ポーリングによりバッチ実行
```

### ① 同期呼び出し (Synchronous Invocation)
* **概要**: 呼び出し元がLambdaの処理完了とレスポンスを待機する。
* **代表的サービス**: Amazon API Gateway、Application Load Balancer (ALB)、AWS SDK。

### ② 非同期呼び出し (Asynchronous Invocation)
* **概要**: イベントを一度キューに投入し、即座に202レスポンスを返してバックグラウンドで処理。失敗した場合は自動的に2回リトライされる。
* **代表的サービス**: Amazon S3、Amazon SNS、Amazon EventBridge。
* **エラーハンドリング**: 処理失敗時のイベント退避先として **DLQ (Dead Letter Queue: SQS/SNS)** や **Lambda Destinations (宛先機能)** を設定可能。

### ③ イベントソースマッピング (Event Source Mapping)
* **概要**: Lambdaがストリーム系サービスを定期的にポーリングし、レコードをバッチ処理する。
* **代表的サービス**: Amazon DynamoDB Streams、Amazon Kinesis、Amazon SQS。

---

## 4. LambdaとVPCアクセス

プライベートVPC内のリソース（RDS、ElastiCacheなど）へアクセスする場合のネットワーク設計です。

* **VPC接続の基本**: Lambda関数をVPC内に配置すると、**Hyperplane ENI (Elastic Network Interface)** を介してVPC内リソースと通信する。
* **インターネット接続**: VPC内に配置したLambdaからインターネットへ通信する場合、パブリックサブネットに放置するだけでは通信不可。**プライベートサブネットにLambdaを配置し、パブリックサブネットのNAT Gatewayを経由**させる必要がある。

---

## 5. コールドスタート問題と対策

Lambdaが長期間呼び出されない場合、初回実行時にコンテナ起動や初期化（Cold Start）のオーバーヘッドが発生します。

* **Proprovisioned Concurrency (割り当て済みコンカレンシー)**:
  * 指定した数の実行環境をあらかじめ初期化・待機させておく機能。
  * コールドスタートによるレイテンシーを回避し、一貫した低応答速度を求められるAPI等に利用する。

---

## 6. セキュリティと権限（IAM）

* **実行ロール (Execution Role)**: Lambda関数自体に付与するIAMロール。他のAWSリソース（S3やDynamoDB、CloudWatch Logsなど）を操作する権限を定義する。
* **リソースベースポリシー (Resource-based Policy)**: 「誰（どのサービス・アカウント）がこのLambda関数を呼び出してよいか」を定義するアクセス権限（例: API Gatewayからの`lambda:InvokeFunction`を許可）。

---

## 7. SAA試験対策・要点チェック

* **実行時間制限**: 処理が15分を超える場合は、AWS Step Functionsでワークロードを複数Lambdaに分割するか、AWS Fargate（ECS/EKS）などのコンテナ実行基盤に切り替える。
* **同時実行数 (Concurrency)**: アカウントごとのデフォルト上限はリージョンあたり 1,000。急激なスケールによるバックエンドDBの枯渇を防ぐため、**Reserved Concurrency (予約済みコンカレンシー)** で上限を制限可能。
* **環境変数とセキュリティ**: データベース接続情報やAPIキーは環境変数に保持し、暗号化には **AWS KMS** や **AWS Systems Manager Parameter Store / Secrets Manager** を併用する。
