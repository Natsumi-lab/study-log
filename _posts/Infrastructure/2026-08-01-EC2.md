## 1. EC2の基本概念

Amazon EC2（Elastic Compute Cloud）は、AWSが提供する安全でサイズ変更可能な**仮想サーバー（コンピューティング機能）**です。

* **AMI（Amazon Machine Image）**: OS（Linux, Windows等）、アプリケーションサーバー、初期設定を含んだテンプレート。
* **インスタンスタイプ**: CPU、メモリ、ストレージ、ネットワーク容量の組み合わせ。
* **EBS（Elastic Block Store）**: EC2にアタッチして使用する永続的なブロックストレージ。

## 2. インスタンスタイプ命名規則とファミリー

SAA試験では、要件に合わせた適切なインスタンスファミリーの選定が問われます。

### 命名規則の例: `t3.micro`
* **t**: ファミリー（T = General Purpose）
* **3**: 世代（数値が大きいほど新しい）
* **micro**: サイズ（nano < micro < small < medium < large ...）

### 主要ファミリーと用途

| ファミリー | タイプ記号 | 主な用途・特徴 | SAAでのキーワード |
| :--- | :--- | :--- | :--- |
| **汎用** | `M`, `T` | Webサーバー、開発環境、小規模DB | バランス型、CPUバースト機能（T系） |
| **コンピューティング最適化** | `C` | ハイパフォーマンスWebサーバー、バッチ処理 | 計算処理重視、バッチ |
| **メモリ最適化** | `R`, `X`, `z` | インメモリキャッシュ（Redis等）、インメモリDB | メモリ大、Redis/Memcached |
| **ストレージ最適化** | `I`, `D`, `H` | データウェアハウス、Hadoop、大規模ログ処理 | 高IOPS、ローカルストレージ（NVMe） |

## 3. 購買モデル（料金体系・インスタンス購入オプション）

コスト最適化（Cost Optimization）はSAAの最重要分野の1つです。

```
[購買モデルの使い分け]
├─ 短期・負荷予測不能 ───────> オンデマンドインスタンス
├─ 定常運用（1〜3年契約） ─────> Reserved Instances / Savings Plans
├─ 中断可能なバッチ処理 ──────> スポットインスタンス
└─ コンプライアンス・ライセンス ─> Dedicated Hosts / Dedicated Instances
```

1. **オンデマンド (On-Demand)**:
   * **特徴**: 前払いなし、秒単位/分単位の従量課金。
   * **用途**: 短期運用、スパイクの発生するワークロード、予測不能なテスト環境。
2. **リザーブドインスタンス (RI) / Savings Plans**:
   * **特徴**: 1年または3年の利用コミットで最大72%割引。
   * **用途**: 定常的・継続的に稼働するデータベースや基幹システム。
3. **スポットインスタンス (Spot Instances)**:
   * **特徴**: AWSの余剰リソースを利用し、最大90%割引。AWS都合で2分前通知ののち中断される可能性がある。
   * **用途**: 中断されても再実行可能なバッチ処理、統計解析、コンテナ環境。
4. **Dedicated Hosts（専有ホスト） / Dedicated Instances（専有インスタンス）**:
   * **特徴**: 他顧客とハードウェアを共有しない専用物理サーバー。
   * **用途**: 厳格なコンプライアンス要件、既存のソケット/コア単位ライセンス（BYOL）の持ち込み。

## 4. ネットワークと配置戦略（Placement Groups）

EC2インスタンスの配置（プレイスメントグループ）を適切に設計することで、パフォーマンスや耐障害性を制御できます。

| 配置戦略 | 特徴 | ユースケース |
| :--- | :--- | :--- |
| **Cluster（クラスタ）** | 1つのAZ内で物理的に近い配置。低レイテンシー＆高スループット。 | HFT（高頻度取引）、HPC、高性能計算 |
| **Spread（スプレッド）** | 各インスタンスを別々の物理ラックに配置（最大7台/AZ）。障害の連鎖を防ぐ。 | 単一障害点を排除したい少数のクリティカルなシステム |
| **Partition（パーティション）** | インスタンス群を論理的パーティションに分け、ラックを分散。 | Hadoop、Cassandra、Kafkaなどの分散データベース |

## 5. 高可用性（HA）とスケーラビリティの実現

SAA試験で最も多く問われるマルチAZ構成および自動スケーリングの基本アーキテクチャです。

* **ELB（Elastic Load Balancing）**: トラフィックを複数AZに跨るEC2に自動分散。
* **Auto Scaling**: 需要に応じてEC2インスタンス数を自動的に増減（スケールアウト/スケールイン）。
* **ステートレス設計**: セッション情報や永続データをEC2ローカルに持たず、ElastiCacheやDynamoDB、S3/EFSに外部化する。

## 6. SAA試験対策・ワンポイントチェック

- [ ] **EBS Root Volumeのデフォルト動作**: EC2削除時にルートボリュームは**デフォルトで自動削除（DeleteOnTermination=True）**される。追加したEBSボリュームはデフォルトで維持される。
- [ ] **ユーザーデータ (User Data)**: 起動時に1回だけ実行されるシェルスクリプト（Webサーバーの初期インストール等に使用）。
- [ ] **メタデータ (Instance Metadata)**: 稼働中のEC2の内部情報（IPアドレス、セキュリティグループ等）を取得。
- [ ] **IAMロールのアタッチ**: EC2からS3やDynamoDB等のAWSサービスへアクセスする場合は、アクセスキーを直書きせず**IAMロール**をEC2に付与する。
