# コストを最適化したアーキテクチャの設計（サイジング）の要点まとめ

AWSにおける「コストを最適化したアーキテクチャの設計（Design Cost-Optimized Architectures）」において、  
リソースの適正サイズ化（ライトサイジング: Right-Sizing）と購買オプション・スケーリングの最適化は、  
無駄なクラウドアカウント費用を抑えつつ十分な性能を確保するためのコア要素です。

過不足のないリソース選定とコスト最適化の設計手法を整理しました。

---

## 1. ライトサイジング（Right-Sizing）の基本原則

ライトサイジングとは、ワークロードの実際のパフォーマンスデータ（CPU、メモリ、ディスクI/O、ネットワーク）を分析し、  
**必要最小限かつ最適なリソースサイズ・インスタンスタイプを選択・変更**するプロセスです。

* **プロビジョニングの過剰（Over-Provisioning）の排除**:
  * 平均CPU使用率やメモリ使用率が極端に低いインスタンス（例: CPU使用率が常時10%以下）は、より小さいサイズ（例: `t3.xlarge` → `t3.medium`）や最新世代（例: `c5` → `c6g` / `c7g`）へダウングレードする。
* **継続的なモニタリングと見直し**:
  * 一度の選定で終わらせず、トラフィックの変動やアーキテクチャの変更に合わせて定期的にリサイズする。

## 2. コスト最適化・推奨ツール

AWSが提供するリソース使用状況の分析・推奨ツールを活用します。

| ツール・サービス | 概要・役割 | 主な機能・特徴 |
| :--- | :--- | :--- |
| **AWS Compute Optimizer** | 機械学習を用いてリソース使用率を分析し、最適なインスタンスタイプを推奨。 | EC2、EBSボリューム、Lambda関数、ECS on Fargate の適正サイズを提案。 |
| **AWS Cost Explorer** | コストと使用状況を可視化・分析・予測。 | RI/Savings Plansの購入推奨、過去12か月の傾向分析、予算超過の予測。 |
| **AWS Trusted Advisor** | ベストプラクティスに基づき、環境全体のチェックと改善案を提示。 | アイドル状態のEC2/RDS、アタッチされていないEIP、使用されていないEBSボリュームを検知。 |
| **AWS Budgets** | コストやリソース使用量が設定した閾値を超えた（または超えると予測された）際に通知・アクションを実行。 | SNSやメール通知、Auto ScalingやIAMポリシーによる自動制限アクション連携。 |

## 3. コンピューティングの購買オプションと使い分け

EC2などの計算リソースは、稼働期間・中断許容度・負荷特性に応じて最適な購入モデルを選択します。

```
[ 購買モデルのコスト最適化マップ ]
├─ 定常的なベースライン負荷（1〜3年利用確実） ─> Savings Plans / Reserved Instances (最大72%削減)
├─ 突発的・予測不能・開発初期 ──────────────> オンデマンド (ベースライン確認用)
├─ 中断可能なバッチ・ステートレスワークロード ──> スポットインスタンス (最大90%削減)
└─ サーバーレス移行可能 ──────────────────────> AWS Lambda / AWS Fargate (実行分のみ課金)
```

### ① Compute Savings Plans vs EC2 Instance Savings Plans
* **Compute Savings Plans**: インスタンスファミリー、サイズ、OS、リージョン、さらには Fargate / Lambda 間をまたいで割引が適用される最も柔軟なプラン。
* **EC2 Instance Savings Plans**: 指定したリージョン内の特定ファミリー（例: 東京リージョンの `m6g` 系）にコミットすることで、より高い割引率を享受。

### ② スポットインスタンス (Spot Instances) の活用
* Auto Scaling グループで**起動テンプレート**を使用し、オンデマンドとスポットを混合配置（例: ベースラインはオンデマンド/RI、追加のスケール分をスポット）。

---

## 4. プロセッサアーキテクチャの選定（AWS Graviton）

* **AWS Graviton プロセッサ（ARMベース）**:
  * AWSが独自設計した ARM ベースのプロセッサ（Graviton2 / Graviton3 / Graviton4）。
  * 同等の x86 ベース（Intel/AMD）インスタンスと比較して、**最大40%優れた価格パフォーマンス（コスト削減 & 性能向上）**を提供。
  * EC2（`t4g`, `m7g`, `c7g`, `r7g` 等）、RDS、ElastiCache、OpenSearch、Lambda で選択可能。

---

## 5. ストレージ・データベースのサイジングとコスト最適化

### ① Amazon EBS の最適化
* **gp2 から gp3 への移行**:
  * `gp3` は `gp2` より容量単価が約20%安価。
  * ストレージ容量を無駄に増やすことなく、必要な IOPS とスループットだけを個別に追加プロビジョニング可能。
* **未使用ボリュームのクリーンアップ**:
  * インスタンス終了時に残ったデタッチ状態（Available）の EBS ボリュームや古いスナップショットを定期削除。

### ② Amazon S3 のライフサイクル管理
* **S3 Intelligent-Tiering**:
  * アクセスパターンが不明または変動するデータに対し、アクセス頻度に応じて自動で階層移動（Frequent ↔ Infrequent ↔ Archive Instant Access）。
* **ライフサイクルルール**:
  * 作成後30日で S3 Standard-IA へ移行、90日で S3 Glacier Flexible Retrieval へ移行、365日で削除、といった自動化。

### ③ Amazon DynamoDB のキャパシティモード
* **オンデマンドモード**: リクエスト数が予測不能、トラフィックが急激にスパイクする、または閑散期が長いワークロード向け（リクエスト単位課金）。
* **プロビジョンドモード + Auto Scaling**: トラフィックが予測可能で安定しているワークロード向け。RI（リザーブドキャパシティ）と併用で大幅コスト削減。
