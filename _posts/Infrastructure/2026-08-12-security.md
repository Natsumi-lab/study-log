# セキュアなアーキテクチャの設計（ネットワークセキュリティ）の要点まとめ

AWSにおける「セキュアなアーキテクチャの設計（Design Secure Architectures）」の中で、  
ネットワークセキュリティは外部からの不正侵入、DDoS攻撃、データ漏洩を防ぐための防御線となる最重要テーマです。

多層防御（Defense in Depth）の考え方に基づき、境界防御からVPC内部のアクセス制御までの主要概念を整理しました。

---

## 1. 境界防御とDDoS対策

インターネットからの攻撃をエッジ（境界）でブロックするためのサービス群です。

| サービス | 役割・特徴 | ユースケース |
| :--- | :--- | :--- |
| **AWS WAF** | Webアプリケーションファイアウォール（L7: アプリケーション層）。SQLインジェクションやXSSなどのWeb攻撃を検知・遮断。 | ALB、Amazon API Gateway、Amazon CloudFront の前段に配置 |
| **AWS Shield** | DDoS攻撃保護サービス。 | |
| └ **Shield Standard** | 自動的に適用される基本保護（L3/L4レベルのSYNフラッド攻撃等）。追加料金なし。 | 全てのAWS利用者に標準適用 |
| └ **Shield Advanced** | 大規模・高度なDDoS攻撃に対する拡張保護機能。24時間365日のDDoSレスポンスチーム(DRT)サポート、コスト保護が付属。 | 大規模エンタープライズ、止めてはならないWebサービス |
| **Amazon CloudFront** | CDN（コンテンツ配信ネットワーク）。エッジロケーションでリクエストを受け取り、オリジンへの直接攻撃を軽減。 | WAFやAWS Shieldと組み合わせてセキュリティ境界を構築 |

---

## 2. VPC内部のアクセス制御（多層防御）

VPC内のネットワークセキュリティは、レイヤーの異なる複数の制御機構を組み合わせる（多層防御）ことが基本原則です。

### Security Group vs Network ACL

```
[ インターネット ]
       │
       ▼
[ Network ACL ] ─────> サブネット単位での制御 (ステートレス / ALLOW & DENY)
       │
       ▼
[ Security Group ] ───> インスタンス(ENI)単位での制御 (ステートful / ALLOWのみ)
       │
       ▼
[ EC2 / Resource ]
```

* **Security Group (セキュリティグループ)**:
  * **単位**: インスタンス（ENI）レベル。
  * **動作**: **ステートフル**（インバウンドを許可した戻りトラフィックは自動的にアウトバウンド許可される）。
  * **設定**: **許可（Allow）のみ**。
  * **参照設計**: 他のセキュリティグループIDを送信元・送信先として指定可能（例: ALBのSGからのアクセスのみをWEBサーバーのSGで許可する）。
* **Network ACL (NACL)**:
  * **単位**: サブネットレベル。
  * **動作**: **ステートレス**（インバウンドとアウトバウンドの両方で明示的な許可が必要）。
  * **設定**: **許可（Allow）および拒否（Deny）の両方**。番号順に評価。
  * **ユースケース**: 特定の悪意あるIPアドレスをピンポイントでブロック（Deny）したい場合。

## 3. プライベート接続とデータ露出の防止

インターネットを経由せずにAWSサービスやオンプレミスと通信を行う仕組みです。

* **VPC Endpoint**:
  * **Gateway Endpoint**: S3およびDynamoDB専用。ルーティングテーブルで制御（無料）。
  * **Interface Endpoint (AWS PrivateLink)**: 多くのAWSサービスやサードパーティサービスに対応。VPC内にプライベートIPを持つENIを配置して通信（有料）。
* **AWS Systems Manager (SSM) Session Manager**:
  * EC2インスタンスにパブリックIPを付与せず、SSH（22番ポート）を開けずにAWSコンソールやCLIから安全にシェルアクセスを提供する機能。
  * 22番ポートのインバウンド開放が不要になるため、SAA試験で強く推奨されるセキュリティパターン。

---

## 4. トラフィックの集約と高度な検査

大規模ネットワークや高度なパケットインスペクションが必要な場合のアーキテクチャです。

* **AWS Network Firewall**:
  * VPC全体のトラフィックをステートフル/ステートレスに詳細検査するマネージド型ファイアウォール。
  * ドメイン名のフィルタリング、URLリストによるアクセス制限、侵入防止システム（IPS）機能を提供。
* **Network Load Balancer (NLB) + Gateway Load Balancer (GWLB)**:
  * サードパーティ製の仮想ファイアウォールアプライアンス（サードパーティ製UTM等）へトラフィックを透過的にルーティング・分散処理する仕組み。

---

## 5. ネットワーク監査とモニタリング

* **VPC Flow Logs (フローログ)**:
  * VPC、サブネット、またはENIレベルでのIPトラフィック（送信元/送信先IP、ポート、ACCEPT/REJECTなど）を記録。
  * ログは CloudWatch Logs または S3 に出力し、セキュリティ分析や不審な通信の検知に利用する。
* **Amazon GuardDuty**:
  * 機械学習と脅威インテリジェンスを用いて、VPC Flow Logs、CloudTrail ログ、DNS ログなどを分析し、悪意あるアクティビティや予期せぬ動作を自動検知する脅威検出サービス。
