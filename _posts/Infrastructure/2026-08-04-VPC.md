# Amazon VPC（Virtual Private Cloud）の要点まとめ

ネットワーク設計の基礎となる **Amazon VPC** の構造とコンポーネントについて  

---

## 1. VPCの基本概念とCIDRブロック

Amazon VPCは、AWSクラウド内に論理的に隔離された仮想ネットワーク空間を定義するサービスです。

* **VPC CIDRブロック**: VPC全体のIPアドレス範囲を設定（例: `10.0.0.0/16`）。
* **サブネット (Subnet)**: VPCをさらに細かく区切ったIPアドレスの範囲（AZ単位で作成）。
  * **パブリックサブネット**: インターネットへの直接アクセスが可能なサブネット（Internet Gateway経由）。
  * **プライベートサブネット**: インターネットからの直接のアクセスを受け付けないサブネット（DBやバックエンドサーバーの配置領域）。

---

## 2. 主要コンポーネントと役割

試験で問われるネットワークコンポーネントの機能と用途の整理です。

| コンポーネント | 役割・特徴 | 主なユースケース |
| :--- | :--- | :--- |
| **Internet Gateway (IGW)** | VPCとインターネット間の双方向通信を可能にするコンポーネント（VPCに1つアタッチ可能）。 | パブリックサブネットのリソースのアウトバウンド/インバウンド通信 |
| **NAT Gateway** | プライベートサブネットからインターネットへのアウトバウンド通信のみを許可する（インバウンドは遮断）。 | パブリックサブネットに配置し、プライベート側のパッチ適用や外部API通信に使用 |
| **Route Table (ルーティングテーブル)** | パケットの送信先を制御するルールの集合。 | サブネットごとにアタッチし、通信経路（IGW宛てやNAT宛てなど）を指定 |
| **Egress-Only Internet Gateway** | IPv6通信専用のアウトバウンド限定ゲートウェイ（IPv4のNAT Gatewayに相当）。 | IPv6環境下での安全な外部通信 |

---

## 3. セキュリティ設定の二大要素（Security Group と Network ACL）

SAA試験で最も混同されやすい2つのネットワークセキュリティ層の相違点です。

| 比較項目 | Security Group (SG) | Network ACL (NACL) |
| :--- | :--- | :--- |
| **適用範囲** | インスタンス（ENI）単位 | サブネット単位 |
| **評価順序** | すべてのルールを評価 | ルール番号の若い順に評価（最初に一致したルールを適用） |
| **ステート（動作）** | **ステートフル**（戻り値の通信は自動許可） | **ステートレス**（アウトバウンド/インバウンド双方の許可が必要） |
| **制御アクション** | **許可（Allow）のみ**定義可能 | **許可（Allow）および拒否（Deny）**の両方を定義可能 |

---

## 4. VPC Endpoint（プライベート接続）

パブリックインターネットを経由せずに、VPC内のプライベートリソースから他のAWSサービス（S3やDynamoDBなど）へ安全に接続するための仕組みです。

```
[ Interface Endpoint (AWS PrivateLink) ] ─ ENIを配置 / 費用が発生 / 多数のサービスに対応
[ Gateway Endpoint ] ────────────────── 費用無料 / ルートテーブル設定 / S3, DynamoDBのみ対応
```

1. **Gateway Endpoint**
   * 対応サービス: **Amazon S3** および **Amazon DynamoDB** のみ。
   * 特徴: 無料。ルートテーブルにターゲットを追加して利用する。
2. **Interface Endpoint (AWS PrivateLink)**
   * 対応サービス: SQS, SNS, Kinesis, CloudWatch等、多くのAWSサービス。
   * 特徴: プライベートサブネット内にENI（プライベートIP）を作成して通信。利用時間とデータ量に応じた課金が発生。

---

## 5. VPCピアリングとTransit Gateway（拠点・VPC間接続）

複数のVPCやオンプレミス環境と連携・接続するための構成オプションです。

* **VPC Peering (VPCピアリング)**:
  * 2つのVPC間を1対1で直接接続する。
  * **推移的ルーティング（Transitive Routing）は不可**（VPC A ↔ VPC B ↔ VPC C と繋いでも A ↔ C は直接通信できない）。
* **AWS Transit Gateway**:
  * 多数のVPCやオンプレミス（VPN/Direct Connect）を中央ハブで集約するスター型構成。
  * ネットワーク構成の簡略化と推移的ルーティングをサポート。
* **AWS Direct Connect (DX)**:
  * オンプレミスとAWS間に専用線を確立。高帯域・安定した通信とセキュリティを提供。

---

## 6. SAA試験対策・要点チェック

* **VPCで予約されているIPアドレス**: 各サブネットのCIDRブロックのうち、**最初と最後の5つのIPアドレス**はAWSによって予約されている（例: `/24` の場合、使用可能IPは256-5=251個）。
* **Flow Logs (VPC フローログ)**: VPC内のIPトラフィック（送信元/送信先IP、ポート、Action: ACCEPT/REJECT等）をキャプチャし、CloudWatch LogsやS3に集約・分析する。
