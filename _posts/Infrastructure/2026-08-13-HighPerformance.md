# 高パフォーマンスなアーキテクチャの設計（ストレージ）の要点まとめ

AWSにおける「高パフォーマンスなアーキテクチャの設計（Design High-Performing Architectures）」の中で、  
ストレージの選定と設計は、入出力処理（I/O）やレイテンシー、スループットがシステム全体の性能ボトルネックになるのを防ぐための重要な要素です。

AWSが提供する主要なストレージサービス（EBS, EFS, S3, Instance Store）の特徴と、要件に応じたパフォーマンス最適化のポイントを整理しました。

---

## 1. Amazon EBS（Elastic Block Store）のパフォーマンス最適化

EC2インスタンスにアタッチして使用するブロックストレージです。SSD系とHDD系の使い分けとボリュームタイプの特徴が頻出します。

### EBSボリュームタイプの比較

| 分類 | ボリュームタイプ | 主な特徴・パフォーマンス指標 | ユースケース |
| :--- | :--- | :--- | :--- |
| **汎用 SSD** | **gp3** | **IOPSとスループットを容量とは独立して個別に調整・プロビジョニング可能**（推奨）。ベース3,000 IOPS / 125 MB/s。 | 仮想デスクトップ、低〜中規模データベース、開発環境 |
| **汎用 SSD** | **gp2** | ボリュームサイズに比例してIOPSが割り振られる（1GBあたり3 IOPS）。 | 過去の標準（gp3への移行が推奨） |
| **プロビジョンド IOPS SSD** | **io2 / io2 Block Express** | 最高レベルのIOPS（最大256,000 IOPS）とサブミリ秒の低レイテンシーを提供。耐久性が高い（99.999%）。 | 大規模・ミッションクリティカルなRDB（Oracle, PostgreSQL, SQL Serverなど） |
| **スループット最適化 HDD** | **st1** | 高スループット（MB/s重視）。低コスト。 | 大規模データウェアハウス、ログ解析、Hadoop/MapReduce |
| **Cold HDD** | **sc1** | 最低コスト。アクセス頻度の低いデータ向け。 | アクセス頻度の低い大容量データの長期保管 |

---

## 2. EC2 インスタンスストア（Instance Store）

* **概要**: EC2のホスト物理サーバーに直結されたローカルNVMe SSDドライブ。
* **パフォーマンス**: EBSをはるかに凌駕する**極めて高いIOPSと超低レイテンシー**を提供。
* **注意点（一時性）**: **エフェメラル（一時的）ストレージ**。インスタンスの停止（Stop）や再起動（ハードウェア障害等）によってデータが消滅する。
* **ユースケース**: 超高パフォーマンスが要求される**一時的なキャッシュ、バッファ、インメモリデータ、スクラッチデータ**（再生成可能なデータ）。

---

## 3. Amazon EFS（Elastic File System）

複数のEC2インスタンス（Linux）から共有アクセス可能な完全マネージド型ネットワークファイルシステム（NFSv4）。

### スループットモードの選定
* **バーストモード (Bursting)**: ストレージ容量の増加に伴ってパフォーマンスがスケールする（標準）。
* **プロビジョンドモード (Provisioned)**: ストレージ容量に関わらず、指定した高スループットを常時確保する。
* **エラスティックモード (Elastic)**: トラフィックの急増・短時間のスパイクに合わせて自動的にスループットを調整（スパイクのあるワークロード向け）。

### パフォーマンスモード
* **汎用モード (General Purpose)**: Webサーバーや開発環境など、多くのワークロードに最適な低レイテンシーモード。
* **最大 I/O モード (Max I/O)**: 数千台のEC2から同時アクセスする並列処理・ビッグデータ解析向け（高スループット重視、レイテンシーはやや増大）。

---

## 4. Amazon S3 のパフォーマンス最適化

大容量オブジェクトストレージである S3 で高いスループットを叩き出すための設計テクニックです。

* **プレフィックスの分散**:
  * S3はプレフィックス（フォルダ階層に相当するパス）ごとに**リクエストレート上限（秒間 3,500 PUT/POST/DELETE, 5,500 GET/HEAD）**を持つ。
  * プレフィックスを分散させることで、リクエスト速度を並列で大幅に向上させることができる。
* **マルチパートアップロード (Multipart Upload)**:
  * 100 MB 以上のファイルをアップロードする際に強く推奨（5 GB 以上は必須）。ファイルパーツを分割して並列送信することで速度を改善し、通信失敗時のリカバリを容易にする。
* **S3 Transfer Acceleration**:
  * 地理的に離れた場所（グローバル）からS3バケットへのデータ転送を高速化。AWSのエッジロケーション（CloudFront網）を経由してデータ転送を行う。
* **S3 Express One Zone**:
  * 一定の単一AZ内でサブミリ秒のデータアクセスを実現する、最も低レイテンシーな高パフォーマンスストレージクラス。

---

## 5. ストレージ選定フロー（要件別）

```
[ ストレージ要件の整理 ]
├─ 超低遅延・高IOPSで一時データ ───────> EC2 インスタンスストア
├─ ミッションクリティカルなDB (要ミリ秒未満) ──> EBS io2 Block Express
├─ コスト重視でフレキシブルなブロックストレージ ─> EBS gp3
├─ 複数Linuxサーバーでのファイル共有 ────> Amazon EFS
└─ 高並列アクセス・大容量オブジェクトデータ ──> Amazon S3 (+ Transfer Acceleration / S3 Express)
```
