監査対象・体制編

---

## 1. 階層別情報セキュリティ監査の全体像

情報セキュリティ監査は、単に現場のシステム設定や機器をチェックするだけでは不十分です。組織のセキュリティは「経営方針（ガバナンス）」から「管理体制（マネジメント）」、そして「日常の実務（オペレーション）」へと連動して機能するため、監査人は**各階層（レイヤー）の役割と責任に応じた監査手続と証拠収集**を行う必要があります。

```
┌─────────────────────────────────────────────────────────────┐
│ ① 経営層・マネジメント層 (ガバナンス層)                     │
│    ・方針策定、リソース配分、リスク受容、説明責任           │
├─────────────────────────────────────────────────────────────┤
│ ② 管理者層 (マネジメント層)                                 │
│    ・規程・ルールの具体化、運用監視、部門間調整、例外管理   │
├─────────────────────────────────────────────────────────────┤
│ ③ 現場・運用層 (オペレーション層)                           │
│    ・手順書の遵守、日次・月次運用、ログ管理、実機設定       │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 各階層における監査の視点と確認項目

### (1) 経営層・マネジメント層（ガバナンスの監査）
経営陣（取締役会、CEO、CIO、CISO等）が情報セキュリティに対するリーダーシップを発揮し、必要な資源と体制を整えているかを検証します。

| 監査の視点 | 主な確認項目 | 収集すべき監査証拠 |
| :--- | :--- | :--- |
| **基本方針の承認と周知** | ・基本方針（情報セキュリティポリシー）を経営陣自らが承認・公布しているか。<br>・定期的に方針の見直しを行っているか。 | ・取締役会や経営会議の議事録<br>・基本方針書の決裁文書・公開履歴 |
| **推進体制とリソース配分** | ・CISO等の責任者を明確に任命しているか。<br>・セキュリティ対策に必要な予算・人員を適切に配分しているか。 | ・組織体制図、職務分掌規程<br>・セキュリティ関連の予算書・決算書 |
| **リスク受容と報告ライン** | ・組織が受容可能なリスク基準を承認しているか。<br>・重大なセキュリティ事故や脆弱性情報が適時に経営陣へ報告されるルートがあるか。 | ・リスクアセスメント結果の承認記録<br>・緊急時エスカレーション規程・報告実績 |
| **マネジメントレビュー** | ・年1回など定期的にセキュリティマネジメントの状況を評価し、改善指示を出しているか。 | ・マネジメントレビュー議事録<br>・経営者からの是正・指示事項の記録 |

---

### (2) 管理者層（マネジメントの監査）
情報セキュリティ委員会、情報システム部門長、各事業部門の管理責任者（アセットオーナー）が、経営方針に基づいて規程を定め、組織的に管理・統制しているかを検証します。

| 監査の視点 | 主な確認項目 | 収集すべき監査証拠 |
| :--- | :--- | :--- |
| **個別規程・基準の整備** | ・アクセス制御、パスワード、外部委託、テレワーク等の個別規程・対策基準を具体的に策定しているか。 | ・各種規程・ガイドライン文書<br>・規程の改訂履歴・承認記録 |
| **資産管理と重要度分類** | ・自部門の情報資産を洗い出し、重要度（機密性・完全性・可用性）に応じた格付けと管理責任者を定めているか。 | ・情報資産管理台帳（インベントリ）<br>・資産オーナー任命記録 |
| **例外承認と変更管理** | ・運用例外（アクセス権の例外付与等）やシステム変更が、所定の申請・承認プロセスを経て行われているか。 | ・変更申請書・承認印<br>・例外利用の申請台帳・見直し記録 |
| **教育訓練と是正処置** | ・従業員への教育計画を策定・実施し、受講状況を管理しているか。<br>・監査や点検での指摘に対する改善計画を策定・推進しているか。 | ・教育計画書、受講率・理解度レポート<br>・是正処置計画書（CAP） |

---

### (3) 現場・運用層（オペレーションの監査）
システム管理者、運用オペレーター、一般従業員、外部常駐スタッフが、定められた手順書やルールを遵守して日常業務を遂行しているかを検証します。

| 監査の視点 | 主な確認項目 | 収集すべき監査証拠 |
| :--- | :--- | :--- |
| **手順書に基づく実務遂行** | ・バックアップ、パッチ適用、アカウント登録・抹消などの作業が手順書通りに実行されているか。 | ・運用チェックシート、作業手順書<br>・作業完了報告書・サイン |
| **技術的設定の整合性** | ・ポリシー通りの設定（パスワード長、MFA、画面自動ロック等）が実機に反映されているか。 | ・OS・ネットワーク機器の設定画面キャプチャ<br>・Active Directoryのグループポリシー設定値 |
| **ログ管理と日常点検** | ・アクセスログやエラーログが定期的に点検・監視され、異常が検知されているか。 | ・ログ監視アラート履歴、日次点検記録簿<br>・ログ保管ストレージの確認 |
| **物理的管理の徹底** | ・入退室ルール、クリアデスク・クリアスクリーン、施錠管理が徹底されているか。 | ・入退室記録簿（ICカードログとの突合）<br>・執務室やサーバ室の実地観察結果 |

## 3. 階層間連携における監査の着眼点（垂直的整合性）

階層別の監査では、個々の階層を独立して見るだけでなく、**「上位の指示が下位に正しく伝達され、下位の実態が上位に正しく報告されているか（垂直的整合性）」**を検証することが不可欠です。

```
【垂直的整合性の検証】
経営方針 (上位) ──[具体化・指示]──► 管理規程 ──[手順化・実行]──► 現場運用 (下位)
       ▲                                                                │
       └──────────────[状況報告・エスカレーション]─────────────────────┘
```

1. **方針と現場運用の乖離（トップダウンの検証）:**
   * 経営層が「全社で多要素認証（MFA）を義務付ける」と宣言していても、現場のシステム設定で一部の特権IDが除外・放置されていないか。
2. **現場の実態と経営報告の乖離（ボトムアップの検証）:**
   * 現場で日常的にセキュリティインシデントや運用例外（パスワード使い回し等）が発生しているにもかかわらず、経営層への報告では「インシデントゼロ・問題なし」と歪曲されていないか。

## 4. 試験対策用：重要キーワード・引っかけパターン

1. **経営層へのヒアリング省略の誤り**
   * *誤答例*：「今回の監査はシステム管理部門を主対象とするため、時間短縮を目的に経営層（CISO等）へのインタビューや基本方針の承認プロセスの確認は全面的に省略した」  
     → **×（ガバナンスおよび組織的コミットメントの検証は監査の前提であり、経営層の関与や方針策定の確認を無条件に省略することは認められない）**
2. **手順書と運用実態の一致確認**
   * *誤答例*：「運用層の監査において、最新の作業手順書が完璧に作成・保管されていたため、実機のシステム設定や日次点検記録の突合を行わずに適合と判定した」  
     → **×（文書の整備状況（設計の妥当性）だけでなく、実際にその通りに運用されているか（運用の有効性）をログや設定値等の客観的証拠で確かめなければならない）**
3. **責任の所在の混同**
   * *誤答例*：「現場担当者がセキュリティポリシーを遵守しなかった場合、その全責任は現場作業者個人にのみ帰属し、管理者層や経営層の管理責任は問われない」  
     → **×（遵守を担保するための教育・訓練、監督体制、システム的な統制（強制力）を整備していなかった場合、管理者層や経営層のマネジメント不備として指摘される）**
