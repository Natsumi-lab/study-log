# 監査意見の決定ロジックと除外事項の判定プロセス
（判定プロセス編 第2部）

---

## 1. 保証型監査における意見表明の4分類

情報セキュリティ監査基準（報告基準）において、保証型監査を実施した場合、監査人は監査証拠および重要性の評価に基づき、以下の**4つの監査意見のいずれか**を表明しなければなりません。

```
┌─────────────────────────────────────────────────────────────┐
│                   保証型監査における意見の類型              │
├──────────────────────────────┬──────────────────────────────┤
│ ① 無限定適正意見 (Unqualified)│ ② 限定付適正意見 (Qualified) │
│    重要な点において適正      │    一部を除き概ね適正        │
├──────────────────────────────┼──────────────────────────────┤
│ ③ 不適正意見 (Adverse)       │ ④ 意見不表明 (Disclaimer)    │
│    全体として不適正          │    証拠不足・制約により      │
│                              │    意見を表明できない        │
└──────────────────────────────┴──────────────────────────────┘
```

---

## 2. 意見表明を左右する2つの要因とマトリクス

監査意見は、**「① 問題の性質（不適合なのか／監査範囲の制約なのか）」**と**「② 影響の度合い（重要だが限定的か／全体に及ぶ広汎なものか）」**の掛け合わせによって厳密に決定されます。

```
┌─────────────────────────────────────────────────────────────────────────┐
│                           意見決定マトリクス                            │
├──────────────────────────┬──────────────────────┬───────────────────────┤
│                          │ 重要だが限定的       │ 広汎（全体的・致命的）│
│        事象の性質        │ (Material but not    │ (Material and         │
│                          │  Pervasive)          │  Pervasive)           │
├──────────────────────────┼──────────────────────┼───────────────────────┤
│ A. 基準の不適合          │                      │                       │
│    (不備・重大な欠陥)    │  ② 限定付適正意見   │  ③ 不適正意見         │
│    ※十分な証拠は入手済  │   (〜を除いて適正)   │   (全体として不適正)  │
├──────────────────────────┼──────────────────────┼───────────────────────┤
│ B. 監査範囲の制約        │                      │                       │
│    (監査証拠の入手不足・ │  ② 限定付適正意見   │  ④ 意見不表明         │
│     手続の未実施)        │   (〜を除いて適正)   │   (意見表明不可)      │
└──────────────────────────┴──────────────────────┴───────────────────────┘
```

## 3. 「限定付適正意見」と「意見不表明」の境界線（最頻出）

試験において最も問われるのが、監査手続に制約（除外事項）が生じた際の**「限定付適正意見」と「意見不表明」の分岐点**です。

### (1) 限定付適正意見（Qualified Opinion）が選ばれるケース
* **条件:**  
  * 監査証拠が入手できなかった領域や手続を実施できなかった範囲が、**「重要ではあるが、監査対象全体から見れば限定的（局所的）であり、他の部分に対する適正性の判断には影響を与えない」**場合。
* **記載方法（除外事項の明記）:**  
  * 「〇〇システムにおけるログ保存手続の不備を除き、重要な点において適正であると認められる」といったように、**どの部分を除外したかを明確に特定して意見表明**を行う。
* **具体例:**  
  * 海外拠点のローカルサーバ1台のみ、現地情勢や通信障害によりログ調査が完了しなかったが、グループ全体の主要基幹システムや主要データセンターの監査手続は完全に実施され適正と確認できた場合。

### (2) 意見不表明（Disclaimer of Opinion）が選ばれるケース
* **条件:**  
  * 監査範囲に対する制約や証拠の欠落が**「著しく広汎（Pervasive）かつ重大」**であり、システム全体・組織全体のセキュリティ状況について合理的な意見を形成するための基礎が完全に失われている場合。
* **記載方法:**  
  * 「〜の理由により十分かつ適切な監査証拠を入手することができなかったため、当監査チームは監査意見を表明しない」と記載する。
* **具体例:**  
  * 根幹となるActive Directoryの全ドメインコントローラのログが消去されており、全社的なアクセス状況が一切検証できない場合。
  * 被監査部門が重要資料の提出を全面的に拒否し、監査計画に定めた主要手続の大半が実施不能となった場合。

---

## 4. 「限定付適正意見」と「不適正意見」の境界線

証拠は十分に入手できているものの、セキュリティ管理基準に対する不適合・重大な欠陥が見つかった場合の判断基準です。

* **限定付適正意見:**  
  * 発見された不備が**局所的・限定的**であり、システム全体を揺るがすものではない場合（例：特定部署におけるパスワード運用ルール違反のみ）。
* **不適正意見（Adverse Opinion）:**  
  * 発見された不備が**広汎・組織全体に波及**しており、全体のセキュリティ管理体制が破綻していると認められる場合（例：経営層によるセキュリティ方針の完全形骸化、全社的な特権ID共用・無管理、基幹データベースの未暗号化・平文流出状態など）。

---

## 5. 試験対策用：重要キーワード・引っかけパターン

1. **意見不表明と不適正意見の混同**
   * *誤答例*：「被監査部門が監査への協力を拒絶し、必要なログを提出しなかったため、監査人は『不適正意見』を表明した」  
     → **×（証拠が入手できていないため、適正・不適正の判断自体が下せない。この場合は『意見不表明』としなければならない）**
2. **広汎性の判断**
   * *誤答例*：「全社の認証基盤全体でログが消失しており、なりすましアクセスの有無が全社規模で確認できない状態であったが、特定システムに限られた問題として限定付適正意見を出した」  
     → **×（認証基盤全体のログ欠損は組織全体に波及する広汎（Pervasive）な事象であるため、意見不表明とすべきである）**
3. **無限定適正意見における軽微な不備の扱い**
   * *誤答例*：「軽微な入力ミスや、重要性の基準値を大幅に下回る些細な是正事項が1件でも検出された場合、無限定適正意見を出すことはできず、必ず限定付適正意見としなければならない」  
     → **×（監査報告書の利用者の判断に影響を与えない軽微な不備であれば、無限定適正意見を表明しつつ、改善提言や監査所見として報告書に記載することが可能）**
