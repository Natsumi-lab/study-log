実務手続編 第2部

---

## 1. 監査手続の二大体系（運用テスト vs 実証テスト）

監査人が十分かつ適切な監査証拠を入手するために実施する監査手続は、目的とアプローチの違いによって**「運用テスト（統制テスト）」**と**「実証テスト（実証手続）」**に大別されます。

```
┌─────────────────────────────────────────────────────────────┐
│                      監査手続の構造                         │
├──────────────────────────────┬──────────────────────────────┤
│ ① 運用テスト (統制テスト)     │ ② 実証テスト (実証手続)      │
│  「仕組みが正しく動いているか」│  「実際のデータ・現物に直接   │
│  （内部統制の有効性の検証）  │    誤りや不備がないか」       │
└──────────────────────────────┴──────────────────────────────┘
```

---

## 2. 運用テスト（Tests of Controls / 統制テスト）

### (1) 目的と定義
* **目的:** 被監査組織が定めた内部統制（ルール、自動チェック機能、承認フロー等）が、**「監査対象期間を通じて継続的かつ有効に運用されていたか」**を確かめる手続。
* **着眼点:** 「ルール通りに承認印が押されているか」「自動パスワード失効機能が常時稼働していたか」「例外承認の申請フローが機能していたか」など、**仕組み（プロセス）自体の信頼性**。

### (2) 主な検証技法
* **閲覧（Inspection）:** 承認申請書、アクセス権変更履歴、定期レビュー議事録などの記録を確認する。
* **質問・観察（Inquiry / Observation）:** 担当者に運用の流れをヒアリングし、実際のオペレーション（入退室手順や機器操作）を目視で確認する。
* **再実施（Reperformance）:** 監査人自身が手順書に従って同じチェック操作を行い、同一の結果が得られるかを確かめる。

---

## 3. 実証テスト（Substantive Tests / 実証手続）

### (1) 目的と定義
* **目的:** データそのもの、システム設定値、物理的現物を直接検証し、**「重要な虚偽、漏洩、不備、不整合が存在しないか」**を直接確かめる手続。
* **着眼点:** 「Active Directoryのアカウント一覧に、既に退職した社員のIDが実際に残っていないか」「機密データベースのアクセス権設定が実際に要件通りになっているか」など、**結果・実態（データ・現物）の正確性**。

### (2) 主な検証技法
* **実査・現物確認:** サーバルーム内の指定ラックの物理的設置状態、保管されている磁気テープの現物照合。
* **分析的手続（Analytical Procedures）:** アクセス件数の月別推移、異常な通信トラフィック、休日のアクセス比率などを比較・分析し、異常値を検知する。
* **詳細テスト（Tests of Details）:** アカウント台帳と人事退職者リストを1件ずつ突合し、不整合（アカウントの残存）を直接洗い出す。

---

## 4. 運用テストと実証テストの比較一覧

| 比較項目 | 運用テスト（統制テスト） | 実証テスト（実証手続） |
| :--- | :--- | :--- |
| **主たる検証対象** | **内部統制（仕組み・ルール・機能）** | **データ、設定値、成果物、現物** |
| **検証する問い** | 「ルールや管理機能は適切に機能しているか？」 | 「実際のデータや設定に誤り・不正はないか？」 |
| **典型的な監査証拠** | 承認印のある申請書、チェックリスト、定期棚卸報告書 | システム生ログ、ADアカウントダッシュボード、現物写真 |
| **サンプリングの焦点** | 運用の「逸脱率（統制ルールが守られなかった割合）」 | エラーや不整合の「重大度・影響件数・金額的損害」 |
| **統制依存との関係** | 統制に依存して監査を効率化するために実施する | 統制の信頼度に関わらず、最終的な正しさを確かめるために実施 |

---

## 5. 監査手続の組合せ（デュアルパーパステストとアプローチ）

実務において、運用テストと実証テストは独立して別々に実施されるだけでなく、効率化のために組み合わせて運用されます。

```
【リスク評価からテスト決定への流れ】
┌─────────────────────────────────────────────────────────────┐
│ 固有リスク (IR) & 統制リスク (CR) の評価                    │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ ① 統制が有効と見込まれる場合 (統制依拠アプローチ)           │
│    ・運用テストを手厚く実施 ──► 統制の有効性を立証          │
│    ・統制が信頼できるため、実証テストのサンプル数を削減可能 │
├─────────────────────────────────────────────────────────────┤
│ ② 統制が脆弱または存在しない場合 (実証アプローチ)           │
│    ・運用テストは省略または最小限                           │
│    ・実証テストを徹底的に実施 (直接データや現物を精査)      │
└─────────────────────────────────────────────────────────────┘
```

* **二重目的テスト（Dual-purpose Test）:**  
  * 1つの監査手続で「運用テスト」と「実証テスト」を同時に行う手法。  
  * *例:* 退職日以降のアクセスログを抽出する作業。  
    * **運用テストの側面:** 「退職者のID即時停止という統制手続が運用されていたか」を検証。  
    * **実証テストの側面:** 「退職者による不正アクセスという重大な事実・被害が実際に存在しないか」を直接検証。

## 6. 試験対策用：重要キーワード・引っかけパターン

1. **運用テストの成否と実証テストの省略**
   * *誤答例*：「運用テストの結果、内部統制が極めて有効に機能していると確認できたため、重要なリスク領域であっても実証テストを完全にゼロ（省略）にして監査を完了した」  
     → **×（内部統制がどれほど良好であっても、内部統制の固有の限界や見逃しリスクがあるため、重要項目について実証手続を完全に省略することは認められない）**
2. **目的の取り違え**
   * *誤答例*：「ユーザーのパスワード変更申請書に上長承認印が押されているかを確認する手続は、実証テストに分類される」  
     → **×（申請承認という「仕組み（内部統制）がルール通り運用されているか」を検証しているため、運用テストに分類される）**
3. **統制が機能していない場合の実証テスト**
   * *誤答例*：「被監査部門において特権ID利用時の事前承認ルールが完全に形骸化していたため、実証テストも実施不能として即座に意見不表明とした」  
     → **×（統制が効いていない場合は、実証テストを強化・拡大して、実際に特権IDの不正使用や改ざんが行われていないかを直接調査・立証する）**
