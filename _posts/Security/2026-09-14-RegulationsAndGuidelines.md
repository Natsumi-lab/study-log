## 1. 政府統一基準群（NISC）および関連法規と監査制度の関係

情報セキュリティ監査は、孤立した技術基準ではなく、国の政策基準や各種法令・社会的要請と密接に連動して機能します。

```
┌─────────────────────────────────────────────────────────────┐
│                      法的・公的要請のピラミッド             │
├─────────────────────────────────────────────────────────────┤
│ ① 法令・規制 (強制)                                        │
│    ・個人情報保護法、マイナンバー法 (行政手続番号法)        │
│    ・不正アクセス禁止法、サイバーセキュリティ基本法         │
├─────────────────────────────────────────────────────────────┤
│ ② 政府・公的基準 (行政機関・調達要件)                       │
│    ・政府機関等のサイバーセキュリティ対策のための統一基準群 │
│    ・ISMAP (政府情報システムのためのセキュリティ評価制度)    │
├─────────────────────────────────────────────────────────────┤
│ ③ 監査基準・管理基準 (民間・社会基盤の評価モノサシ)         │
│    ・経産省 監査基準 / 管理基準                             │
│    ・JASA 各種技術指針・実践ガイドライン                    │
└─────────────────────────────────────────────────────────────┘
```

---

### (1) 政府機関等のサイバーセキュリティ対策のための統一基準群（NISC）
* **策定主体:** 内閣サイバーセキュリティセンター（NISC）
* **対象:** 各府省庁、独立行政法人、指定法人等
* **監査との関係:**
  * 政府統一基準群では、府省庁自らが行う「自己点検」に加え、**「内部監査」および「外部監査（第三者監査）」の定期的実施が義務付け**られている。
  * 政府統一基準に準拠した監査を行う際、実務的な監査手続きや監査人の資格要件として、経済産業省の監査基準およびJASA監査人制度が参照・活用される。

---

### (2) 個人情報保護法およびマイナンバー法（番号法）との関係

| 法令 | 法的要求と監査上の位置づけ | 監査で特に確認すべき統制ポイント |
| :--- | :--- | :--- |
| **個人情報保護法** | ・安全管理措置（組織的・人的・物理的・技術的）の講定義務。<br>・漏えい発生時の報告義務・本人通知義務。<br>・委託先の監督義務。 | ・委託先に対する監査の実施状況（再委託先含む）。<br>・安全管理措置がガイドライン等に沿って文書化・運用されているか。 |
| **マイナンバー法**<br>（特定個人情報の適正な取扱い） | ・個人情報保護法よりも**さらに厳格な保護措置**を義務付け。<br>・利用目的の限定（社会保障、税、災害対策のみ）。<br>・特定個人情報保護評価（PIA）の実施。 | ・特定個人情報ファイルを扱うシステムの**アクセス権限の極小化**。<br>・管理区域・取扱区域の明確な物理的境界分離。<br>・独立した内部点検・監査の実施記録。 |

## 2. JASA（日本セキュリティ監査協会）が公開する各種指針・ガイドライン

経済産業省の基本基準を補完し、現場での監査実務を標準化・具体化するために、JASAは多数の実践的なガイドライン（技術指針）を策定しています。

```
┌─────────────────────────────────────────────────────────────┐
│                      JASA 技術指針・手引群                   │
├───────────────────┬───────────────────┬─────────────────────┤
│  ① 監査手続・技法 │  ② クラウド分野    │  ③ 特定業種・テーマ  │
│  ・監査実施の手引 │  ・クラウド監査    │  ・医療・IoT・委託先│
│  ・サンプリング   │    ガイドライン   │    管理指針         │
└───────────────────┴───────────────────┴─────────────────────┘
```

### (1) クラウドセキュリティ監査ガイドライン
* **策定背景:** クラウド（IaaS, PaaS, SaaS）の普及に伴い、責任共有モデル（事業者側と利用者側の責任分界点）に基づく監査が必要になったため。
* **CSマーク制度（クラウド情報セキュリティ監査制度）:**
  * クラウド事業者がJASAの基準に基づく外部監査を受け、適合性が認められた場合に「CSマーク（ゴールド／シルバー）」を付与・公開する仕組み。
  * クラウド利用企業は、このマークや監査報告書を確認することで、委託先監査の負担を大幅に軽減できる。

### (2) その他の主要ガイドライン
* **委託先（サプライチェーン）セキュリティ監査ガイドライン:**
  * 外部委託や再委託先における管理状況を効率的・効果的に確認するための手順やチェックリストを提供。
* **情報セキュリティ監査実施の手引き:**
  * 監査計画の立案から、予備調査、本調査（往査・インタビュー・サンプリング）、調書の作成、報告書提出までの標準的な実務プロセスを詳述。
* **特定分野向けガイドライン（医療情報、スマート工場、テレワーク等）:**
  * 業種ごとの法規制（厚労省3省2ガイドライン等）や新たな就労形態に合わせた監査手順の指針。

## 3. 試験対策用：重要キーワード・引っかけパターン

1. **マイナンバー（特定個人情報）の取扱規程**
   * *誤答例*：「特定個人情報は個人情報の一種であるため、一般の個人情報取扱規程と全く同一の安全管理措置で運用していれば法令上問題ない」 → **×（マイナンバー法では一般の個人情報よりも厳格な物理的分離・利用制限・厳密なログ管理等が求められる）**
2. **クラウドサービス利用時の監査責任**
   * *誤答例*：「大手クラウド事業者のIaaSを利用している場合、インフラ基盤の安全性は事業者が担保しているため、利用企業側の設定やアクセス管理について監査する必要はない」 → **×（責任共有モデルに基づき、利用者側が管理責任を持つ領域（OS・ミドルウェア・アクセス権・暗号化等）は利用企業側の監査対象となる）**
3. **NISC統一基準の適用範囲**
   * *誤答例*：「NISCの政府機関統一基準群は、国内のすべての民間企業にも一律に遵守義務が課されている」 → **×（主たる適用対象は中央省庁・行政機関・独立行政法人等。民間企業は参考として活用するか、政府調達の参入要件となる）**
