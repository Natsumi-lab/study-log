## 1. CAIS 監査基準・管理基準の全体体系と位置づけ

情報セキュリティ監査制度（経済産業省）は、**「情報セキュリティ監査基準」**と  
**「情報セキュリティ管理基準」**の2つの基準を中核として構成されています。

```
【情報セキュリティ監査制度の基本構造】
┌─────────────────────────────────────────────────────────┐
│ ① 情報セキュリティ監査基準 (行為基準)                      │
│    監査人の「あるべき姿勢・行動・手続き・報告」を規定      │
│    ├─ 一般基準 (監査人の適格性・心構え)                 │
│    ├─ 実施基準 (監査計画～証拠収集・評価の手続き)        │
│    └─ 報告基準 (監査報告書の記載事項・意見表明)          │
└─────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────┐
│ ② 情報セキュリティ管理基準 (判断基準)                      │
│    組織が講じるべきセキュリティ対策・コントロールを体系化  │
│    (ISO/IEC 27001 / JIS Q 27001 等との整合性)            │
└─────────────────────────────────────────────────────────┘
```

## 2. 情報セキュリティ監査基準の3部構成と重要定義

### (1) 一般基準（監査人の適格性および遵守事項）
監査人が監査業務を行うにあたり備えるべき**資格、能力、姿勢、倫理**を定めたもの。

| 項目 | 規定内容・重要キーワード | 試験頻出ポイント |
| :--- | :--- | :--- |
| **① 目的** | 情報セキュリティ監査の品質確保と信頼性の向上を図ること。 | 監査の社会的信頼を高めるための規範。 |
| **② 独立性** | 監査人は、被監査主体から**精神的・外観的に独立**していなければならない。<br>・**精神的独立性**：公正不偏の態度、偏見・先入観の排除。<br>・**外観的独立性**：第三者から見て利害関係（親子会社関係、直前の業務担当、金銭的利害など）がない状態。 | 「過去に自身が設計・構築したシステムを自分で監査してはならない（自己監査の禁止）」「コンサルティング業務と保証型監査の兼任制限」が問われる。 |
| **③ 職業倫理と誠実性** | 高い職業倫理意識を保持し、誠実・公正に業務を遂行すること。守秘義務の厳守。 | 監査業務で知り得た情報の漏洩・私的利用の禁止（守秘義務は契約終了後も継続）。 |
| **④ 専門能力と経験** | 監査人は、IT技術、情報セキュリティ、監査技法、関連法規に関する**十分な専門知識と実務経験**を有していなければならない。 | 継続的な専門知識の維持・向上（継続教育/CPE）が求められる。単独で能力が不足する場合は専門家の利用を検討する。 |
| **⑤ 正当な注意** | 職業的専門家としての**正当な注意（Due Professional Care）**を払わなければならない。 | 「過度な完全主義」ではなく、専門家として通常期待される注意深さと判断基準を意味する。 |
| **⑥ 監査の品質管理** | 監査業務が監査基準に準拠して適切に実施されるよう、監査の品質管理体制を整備・運用すること。 | 監査チーム内での相互レビュー、監査調書の適切な作成・保管体制。 |

---

### (2) 実施基準（監査手続き・実務プロセス）
監査計画の立案から証拠収集、評価に至る**実務プロセスの一連のルール**。

| 項目 | 規定内容・重要キーワード | 試験頻出ポイント |
| :--- | :--- | :--- |
| **① 監査計画の策定** | 監査目的、対象範囲（スコープ）、監査手順、スケジュール、要員配置を定めた**監査基本計画書**および**監査個別計画書**を作成する。 | 監査リスク（固有リスク、統制リスク）を勘案し、重要性の基準値を設定してメリハリをつける。 |
| **② リスクアプローチ** | すべてを網羅するのではなく、リスクの高い領域に監査資源を重点配分する手法。 | 「悉皆（全件）監査」ではなく、サンプリングやリスク評価に基づく効率的・効果的監査を実施する。 |
| **③ 監査証拠の収集と評価** | 監査意見・結論の根拠となる**十分かつ適切な監査証拠**を入手する。<br>・**十分性**（量的基準）：意見形成に足りる量。<br>・**適切性**（質的基準）：関連性および信頼性（外部入手証拠 ＞ 内部作成証拠、直接観察 ＞ 伝聞）。 | 「客観的な裏付け証拠」なしに被監査者の言明（口頭説明）のみで結論を出してはならない。 |
| **④ 監査技法** | **閲覧、観察（立会）、質問（インタビュー）、再計算、再実施、分析的手続き、確認**などの技法を適切に組み合わせる。 | 技法ごとの特性（例：質問だけでは証拠能力が低いので、ログ閲覧や現地観察で裏付ける）を理解すること。 |
| **⑤ 監査調書の作成・保存** | 実施した監査手続き、入手した証拠、下した判断と結論を記録した**監査調書（ワークペーパー）**を作成・保管する。 | 「他の経験ある監査人が調書を読んだ際に、同じ結論に至るだけの記録（自己完結性）」が必要。 |

---

### (3) 報告基準（監査結果の伝達・意見表明）
監査結果を依頼者・利害関係者へ報告する際の**記載要件と報告ルール**。

| 項目 | 規定内容・重要キーワード | 試験頻出ポイント |
| :--- | :--- | :--- |
| **① 監査報告書の作成と提出** | 監査人は、実施した監査の結果を取りまとめ、遅滞なく**情報セキュリティ監査報告書**を作成し、監査依頼者に提出する。 | 監査報告書には監査人の署名・捺印が必要。作成日付は監査手続き完了日。 |
| **② 記載事項** | ・監査の目的、対象範囲、実施期間<br>・準拠した監査基準・管理基準<br>・実施した監査手続きの概要<br>・**監査意見または結論（保証型または助言型）**<br>・発見事項（指摘事項・推奨事項）<br>・除外事項、制約事項 | 報告書に必ず含まれるべき「基本的記載事項」を覚える。 |
| **③ 監査意見の類型（保証型監査の場合）** | ・**無限定適正意見**：重要な点において適正であると認められる。<br>・**限定付適正意見**：一部の重要事項を除き、概ね適正である。<br>・**不適正意見**：全体として不適正である。<br>・**意見不表明**：証拠不足や制約により意見を表明できない。 | 保証型監査における意見の4分類と、それぞれの適用条件。 |
| **④ 助言型監査の報告** | 指摘事項（現状のギャップや課題）と、それに対する**具体的な改善提言（推奨事項）**を明確に記載する。 | 助言型では意見表明（適正/不適正の判定）ではなく、改善提案が中心となる。 |
| **⑤ フォローアップ** | 報告書提出後、被監査主体による改善措置の進捗状況を確認する手続き。 | 改善実施そのものは「被監査主体の責任」であり、監査人の役割は「改善状況の確認・評価」である点。 |

## 3. 保証型監査と助言型監査の比較

| 比較項目 | 保証型監査（Assurance） | 助言型監査（Advisory / Consulting） |
| :--- | :--- | :--- |
| **主たる目的** | セキュリティ対策が基準に準拠しているかの「**保証**」を利害関係者に提供する | 被監査主体のセキュリティレベル向上のための「**助言・改善提案**」を行う |
| **報告書の受け手** | 主に経営陣、取締役会、外部ステークホルダー、顧客等 | 主に被監査部門の責任者、情報セキュリティ推進責任者等 |
| **結論の形式** | 意見表明（無限定適正 / 限定付適正 / 不適正 / 意見不表明） | 監査所見（発見事項）＋ 改善提言（推奨事項） |
| **監査人の姿勢** | 厳格な独立性と客観性が最優先 | 独立性を保ちつつも、組織の実情に寄り添った実行可能性を重視 |

## 4. 試験対策用：重要キーワード・引っかけパターン

1. **自己監査の禁止（外観的独立性）**
   * *誤答例*：「構築担当者であっても、公平な心を持っていれば（精神的独立性があれば）監査してよい」 $
ightarrow$ **×（外観的独立性を損なうため不可）**
2. **監査証拠の信頼性**
   * 外部から直接入手した証拠 ＞ 内部で作成された文書
   * 原本 ＞ コピー
   * 監査人が直接観察・検証した事実 ＞ 被監査者の口頭説明
3. **保証の限界（絶対的保証ではない）**
   * 監査人が提供するのは「**合理的な保証**」であり、「絶対的な無欠陥・安全」を保証するものではない（サンプリングに伴う固有の限界、内部統制の限界、不正の共謀などがあるため）。
4. **改善実施の責任の所在**
   * 指摘された課題に対する**改善措置の策定・実行は「被監査主体（経営者・現場）」の責任**。監査人が直接システム設定を変更したり改善作業を代行することは、独立性を侵害するため禁止。
