実務手続編 第1部

---

## 1. 試査（サンプリング監査）の基本概念

情報セキュリティ監査において、対象となる全ての事象・記録を網羅的に調べる「精査（全件調査）」を行うことは、コスト・時間・工数の制約から現実的ではありません。  
そのため、全体の傾向や統制の有効性を推測・評価するために一部の項目を抽出して検証する**「試査（サンプリング監査）」**が原則として用いられます。

```
┌─────────────────────────────────────────────────────────────┐
│ 精査 (100% 全件検証)                                        │
│ ・対象件数がごく少数 (例: 年間数件の特権ID申請)             │
│ ・極めて高いリスク・重大性がある領域                        │
├─────────────────────────────────────────────────────────────┤
│ 試査 (サンプリング監査) ★基本はこちらを実施                │
│ ・母集団から代表的なサンプルを抽出して検証                  │
│ ・サンプルの検証結果から母集団全体の状況を推定              │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 母集団（Population）の確定と留意点

サンプリングを正しく機能させるための大前提として、**母集団を適切に定義・画定**する必要があります。

### (1) 母集団に求められる3つの要件

| 要件 | 定義 | 実務上の具体例・着眼点 |
| :--- | :--- | :--- |
| **① 網羅性（完全性）** | 監査対象期間・範囲の全てのデータが漏れなく含まれていること。 | 4月〜翌年3月が監査対象である場合、特定の月やシステム更新前後のログが欠落していないか確認する。 |
| **② 適切性（適合性）** | 監査目的と直接合致するデータ群であること。 | 「一般ユーザーのPWリセット申請」を検証したい母集団に、「システム管理者権限の申請」が混在していないか確認する。 |
| **③ 信頼性** | 母集団となる台帳やログ自体が改ざん・欠損していないこと。 | 提出されたExcel台帳が、システムから直接エクスポートされた生データと一致しているかを突合する。 |

> **【試験頻出の落とし穴】**  
> 被監査部門が意図的・過失により「不都合な記録を除外した母集団」を提示してくるリスクを想定し、監査人は**母集団の抽出条件・件数整合性を自ら検証**しなければなりません。

## 3. 有意抽出と統計的サンプリングの使い分け

サンプリング手法は、統計理論に基づく**「統計的サンプリング」**と、監査人の判断・着眼点に基づく**「非統計的サンプリング（有意抽出）」**に分類されます。

```
┌─────────────────────────────────────────────────────────────┐
│                      サンプリング手法の分類                 │
├──────────────────────────────┬──────────────────────────────┤
│ ① 非統計的サンプリング (有意抽出)│ ② 統計的サンプリング (無作為抽出)│
│  監査人の経験・リスク判断で選択│  確率論・乱数を用いて客観的に選択│
└──────────────────────────────┴──────────────────────────────┘
```

### 比較一覧表

| 比較項目 | 有意抽出（非統計的サンプリング） | 統計的サンプリング（確率的抽出） |
| :--- | :--- | :--- |
| **抽出の基準** | 監査人の**経験、専門的判断、リスクの大小**に基づく | **確率論、無作為抽出（乱数テーブル等）**に基づく |
| **主な抽出対象** | ・高額・重要度の高い案件<br>・深夜・休日の異例なアクセス<br>・過去に不備・インシデントがあった担当部署<br>・形式不備が見られる申請 | 母集団全体（全サンプルが等しい確率で抽出対象となる） |
| **長所（メリット）** | ・リスクが高い箇所をピンポイントで狙い撃ちできる<br>・抽出作業がシンプルで実務負荷が低い | ・抽出に監査人の主観や偏見が入らない<br>・サンプリングリスク（誤差）を数学的・客観的に測定可能 |
| **短所（デメリット）** | ・サンプリングリスクを客観的に数値化できない<br>・結果を母集団全体に確率論的に拡大推計することはできない | ・統計理論の知識が必要<br>・ある程度の母集団件数（規模）が必要となる |
| **主な適用場面** | ・リスクの高い例外事項・不審な取引の検出<br>・母集団が小さく、ばらつきが大きい場合 | ・大量の定型トランザクション（日常的なログ照合等）<br>・統制の運用逸脱率（不備率）を客観的に検証したい場合 |

## 4. サンプリングリスク（Sampling Risk）

サンプリングを実施する以上、**「抽出したサンプルがたまたま母集団全体を代表していなかったために生じる誤判断のリスク」**が必ず伴います。

* **過大信頼のリスク（ベータ・リスク / 第2種の過誤）:**  
  * 実際には内部統制が有効でない（不備が多い）のに、抽出したサンプルがたまたま正常だったため、**「有効である」と誤って高く評価してしまうリスク**。  
  * **監査上の影響:** 見逃し（発見リスクの増大）につながり、監査の有効性を著しく損なうため、最も警戒すべきリスク。
* **過小信頼のリスク（アルファ・リスク / 第1種の過誤）:**  
  * 実際には内部統制が十分に有効であるのに、抽出したサンプルにたまたま不備が含まれていたため、**「有効でない」と誤って低く評価してしまうリスク**。  
  * **監査上の影響:** 不要な追加調査が発生し、監査の効率性が損なわれる。

## 5. 試験対策用：重要キーワード・引っかけパターン

1. **有意抽出の結果推計**
   * *誤答例*：「リスクの高い取引を有意抽出して検証した結果、10件中5件に不備が見つかったため、母集団全体（1,000件）の50%にあたる500件に不備が存在すると統計的に断定した」  
     → **×（有意抽出は偏りを持たせて抽出しているため、母集団全体のエラー率に数学的・確率論的に拡大推計することはできない）**
2. **統計的サンプリングにおける主観の排除**
   * *誤答例*：「統計的サンプリングを実施する場合、監査人の専門的判断は一切不要となる」  
     → **×（許容エラー率や信頼水準、母集団の確定などの前提設定には監査人の高度な専門的判断が必要）**
3. **精査の選択基準**
   * *誤答例*：「情報セキュリティ監査においては、いかなる場合も効率化のためにサンプリングを実施しなければならない」  
     → **×（件数が極めて少ない重要項目や、特権IDの不正利用等のクリティカルな領域では精査（全件調査）を実施する）**
