## 1. 被監査主体の「言明（アサーション）」と監査人の責任

情報セキュリティ監査において、**「セキュリティ対策を整備・運用する責任」**と**「それを検証・評価する責任」**は明確に分担されています。

```
┌─────────────────────────────────────────────────────────────┐
│                    二重責任の原則 (分担関係)                 │
├──────────────────────────────┬──────────────────────────────┤
│  被監査主体 (経営者・管理者) │       監査人 (Auditor)       │
├──────────────────────────────┼──────────────────────────────┤
│ ・セキュリティ対策の整備・運用 │ ・監査手続の計画・実施       │
│ ・言明 (アサーション) の提示 │ ・監査証拠の収集・評価       │
│ ・説明責任 (アカウンタビリティ)│ ・事実認定および監査意見/助言│
└──────────────────────────────┴──────────────────────────────┘
```

### (1) 被監査主体の「言明（アサーション）」とは
* **定義:** 被監査主体が、自社の情報セキュリティ管理策や運用実態について**「基準に準拠して適切に整備・運用されている」と主張・表明すること**。
* **具体例:**
  * 「当社の全従業員は年1回以上のセキュリティ教育を受講しています」
  * 「退職者のアカウントは退職日当日に速やかに削除されています」
  * 「本番環境へのアクセス権は必要最小限に制限されています」
* **監査上の位置づけ:**
  * 言明はあくまで**「被監査主体の主張」**に過ぎない。
  * 監査人は、被監査主体の言明を鵜呑みにしてはならず、**「言明が事実と一致しているか」を監査証拠によって確かめる**ことが任務となる。

### (2) 監査人の責任
* 監査人の責任は、**「収集した十分かつ適切な監査証拠に基づいて、客観的な意見表明または助言を行うこと」**にある。
* **責任の限界:**
  * 監査人はシステムの安全性について**「絶対的な保証」を行う責任は負わない**（合理的な保証にとどまる）。
  * 指摘事項に対する**改善措置を策定・実施する責任は被監査主体側**にあり、監査人が是正作業を直接代行する責任は負わない（代行すると外観的独立性を損なう）。

## 2. 事実認定（ファクトファインディング）のプロセス

事実認定とは、被監査主体の言明や現状について、**客観的な証拠に基づいて「何が事実であるか」を客観的に確定する行為**です。

```
【事実認定の流れ】
┌───────────────┐      ┌───────────────┐      ┌───────────────┐      ┌───────────────┐
│  ① 言明の受領  │ ───► │  ② 証拠の入手  │ ───► │  ③ 証拠の評価  │ ───► │  ④ 事実認定   │
│ (被監査者の主張)│      │(閲覧・観察等) │      │(整合性・信頼性)│      │ (客観的事実)  │
└───────────────┘      └───────────────┘      └───────────────┘      └───────────────┘
                                                                             │
                                                                             ▼
                                                                     ┌───────────────┐
                                                                     │ 基準との照合  │
                                                                     │ (適合/不備等) │
                                                                     └───────────────┘
```

* **重要ルール:**
  * **主観や推測の排除:** 「おそらくやっているだろう」「担当者がそう言っていたから」という主観や伝聞で事実を確定してはならない。
  * **反証可能性と裏付け:** 異なる角度から複数の証拠を照合し、矛盾がないことを確認する（例：本人の「教育を受講した」という言明に対し、受講ログや理解度テスト結果を照合）。
  * **監査調書への記録:** 認定した事実は、後から第三者が検証できるように**監査調書に証拠とともに明記**しなければならない。

## 3. 監査証拠の種類

監査人が事実認定および意見形成のために収集する証拠には、以下の分類があります。

| 証拠の分類 | 内容・具体例 | 証拠力・特徴 |
| :--- | :--- | :--- |
| **① 物理的証拠 (Physical Evidence)** | サーバルームの施錠状態、監視カメラ、生体認証装置、防災設備などを**現地で直接観察・確認**したもの。 | **証拠力：極めて高い**<br>監査人が自らの目で現物を確認するため、偽造の余地が少ない。 |
| **② 文書・記録証拠 (Documentary Evidence)** | 情報セキュリティ規程、運用手順書、契約書、ログファイル、申請書・承認印、議事録など。 | **証拠力：中〜高**<br>外部作成文書（ベンダー請求書、第三者証明書）は内部作成文書（社内メモ、日報）より信頼性が高い。 |
| **③ 口頭証拠 (Oral / Testimonial Evidence)** | 被監査部門の責任者や担当者に対する**インタビュー（質問）による回答**。 | **証拠力：低い（単体では不可）**<br>口頭説明のみで事実認定することはできない。必ず文書証拠や物理的証拠による裏付け（コロボレーション）が必要。 |
| **④ 電子的証拠 (Electronic Evidence)** | アクセスログ、DB更新履歴、設定変更履歴、メール送受信履歴、設定画面のスナップショットなど。 | **証拠力：中〜高**<br>改ざんが容易な性質があるため、ハッシュ値の取得やタイムスタンプ、特権ID管理の厳格性が信頼性の前提となる。 |
| **⑤ 分析的証拠 (Analytical Evidence)** | トレンド分析、過去データとの比較、比率分析、異常値検出などによって導き出された推論結果。 | **証拠力：中**<br>リスク領域の特定や異常兆候の検知に有効だが、最終判定には直接証拠が必要。 |

## 4. 監査証拠の「十分性」と「適切性」

監査人は意見を表明するにあたり、**「十分かつ適切な監査証拠（Sufficient and Appropriate Audit Evidence）」**を入手しなければなりません。

```
┌────────────────────────────────────────────────────────┐
│               十分かつ適切な監査証拠                    │
├──────────────────────────┬─────────────────────────────┤
│   十分性 (Sufficiency)    │      適切性 (Appropriateness)│
│     【 量 的 尺 度 】    │          【 質 的 尺 度 】   │
│  意見表明に足りる「証拠の量」│  証拠の「関連性」＋「信頼性」│
└──────────────────────────┴─────────────────────────────┘
```

### (1) 十分性（量的尺度）
* **定義:** 監査人が合理的な結論を導き出すために必要な**「証拠の量」**。
* **影響要因:**
  * **固有リスク・統制リスクの高さ:** リスクが高い項目ほど、多くのサンプル件数・証拠が必要。
  * **重要性（マテリアリティ）:** 業務に与えるインパクトが大きい項目ほど、証拠の量が求められる。
  * **証拠の質:** 証拠の質（適切性）が高ければ、必要な証拠の量は少なくて済む（ただし、質の低さを量だけで完全に補うことはできない）。

### (2) 適切性（質的尺度）
* **定義:** 監査証拠の**「関連性（Relevance）」**と**「信頼性（Reliability）」**。
  * **関連性:** 監査の目的や、確かめようとしている「言明」に直接関係しているか。
  * **信頼性:** その証拠がどれだけ信用に足る情報源・性質を持っているか。

#### 【最頻出】監査証拠の信頼性の高低ルール
監査証拠の信頼性を比較する問題は試験で最もよく出題されます。

| 信頼性が高い条件 | 信頼性が低い条件 | 理由・背景 |
| :--- | :--- | :--- |
| **外部の情報源** から入手した証拠 | **内部の情報源** から入手した証拠 | 外部の独立した第三者が作成した情報の方が、利害関係による改ざんリスクが低いため。 |
| **有効な内部統制の下** で作成された証拠 | **統制が不十分な環境** で作成された証拠 | 適切な承認フローやアクセス制限が効いている環境のログ・文書は改ざんされにくいため。 |
| 監査人が **直接入手・観察** した証拠 | 被監査者を通じて **間接的に入手** した証拠 | 又聞きや仲介を挟むと、意図的な選別や誤謬が混入する恐れがあるため。 |
| **文書・現物**（書面・電子的記録） | **口頭** による陳述 | 文書は客観的記録として残るが、口頭は主観や記憶違い、言い逃れが生じやすいため。 |
| **原本** | **コピー・転記物** | 複写・転記の過程で改ざんや欠落が生じる可能性があるため。 |

## 5. 試験対策用：重要キーワード・引っかけパターン

1. **口頭証拠の単独利用**
   * *誤答例*：「担当役員から『運用ルールは完全に遵守されている』との明確な口頭回答を得たため、適正であると事実認定した」 $
ightarrow$ **×（口頭証拠だけでは不可。ログや承認履歴などの客観的証拠による裏付けが必要）**
2. **証拠の量と質のトレードオフ**
   * *誤答例*：「証拠の質が著しく低い場合であっても、サンプリング数を大幅に増やして大量に集めれば、適切性の不足を補うことができる」 $
ightarrow$ **×（信頼性のない証拠をいくら大量に集めても、適切性は満たされない）**
3. **二重責任の原則の混同**
   * *誤答例*：「監査人は、情報セキュリティ対策に不備が見つかった場合、自らポリシーを改訂しシステム設定を修正する責任を負う」 $
ightarrow$ **×（改善策の実施は被監査主体の責任。監査人が代行すると自己監査となり独立性違反）**
4. **原本とコピーの信頼性**
   * *誤答例*：「被監査部門が提出した承認申請書のコピーは、原本と同一内容であると担当者が言明しているため、原本と同等の信頼性がある」 $
ightarrow$ **×（原則として原本を直接確認するか、原本照合の手続きが必要）**
