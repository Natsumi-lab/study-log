## 1. 組織的管理策（Organizational Controls）

組織全体の運営、ガバナンス、ポリシー、外部委託、継続性などに関する管理策群です。監査では主に**経営層・セキュリティ委員会・管理部門**がヒアリング対象となります。

| 管理策領域 | 具体的な対策内容 | 監査での確認ポイント・証拠 |
| :--- | :--- | :--- |
| **情報セキュリティ方針** | 経営陣が承認したセキュリティ基本方針・対策基準の策定と全社への周知。定期的な見直し。 | ・経営陣の承認署名・決裁記録<br>・社内ポータル等への公開履歴<br>・年1回または環境変化時の改訂記録 |
| **役割と責任の明確化** | 情報セキュリティ責任者（CISO）、推進担当者、資産管理者の任命と職務分掌。 | ・組織体制図、職務分掌規程<br>・利益相反を防ぐための牽制体制（開発と運用の分離など） |
| **資産管理と情報分類** | 情報資産目録の作成、機密性・完全性・可用性（CIA）に基づく資産の重要度分類とラベル表示。 | ・最新の情報資産台帳<br>・ラベリング（極秘・社外秘・公開等）の実施状況<br>・管理責任者（アセットオーナー）の指定 |
| **供給者（サプライヤー）関係** | クラウド事業者、開発委託先、保守ベンダー等との契約におけるセキュリティ要求条項と定期監査。 | ・委託先選定基準、秘密保持契約（NDA）<br>・SLA（サービスレベル合意書）<br>・外部ベンダーに対する定期評価・報告受領記録 |
| **インシデント管理** | セキュリティ事故発生時の報告ルート、初動対応手順、エスカレーション基準、再発防止策。 | ・インシデント対応手順書（CSIRT体制）<br>・過去のインシデント報告書、原因分析・是正処置記録<br>・連絡体制図・緊急連絡網の更新頻度 |
| **事業継続管理（BCP / ICT継続性）** | 災害・サイバー攻撃時の重要業務復旧計画、RTO（目標復旧時間）/ RPO（目標復旧時点）の定義と訓練。 | ・事業影響度分析（BIA）結果文書<br>・BCP手順書、IT復旧手順書<br>・年1回以上の訓練・演習実績報告書 |

## 2. 人的管理策（People Controls）

役員、正社員、契約社員、派遣社員、外部委託スタッフなど、「人」に起因する情報漏洩や不正を防ぐための管理策です。監査では主に**人事部門・総務部門**がヒアリング対象となります。

```
【人的管理策のライフサイクル】
┌──────────────────┐      ┌──────────────────┐      ┌──────────────────┐
│  ① 採用・雇用前   │ ───► │   ② 雇用・在職中  │ ───► │  ③ 異動・退職時   │
│ 背景調査、NDA締結 │      │ 教育訓練、誓約書 │      │ アカウント剥奪   │
└──────────────────┘      └──────────────────┘      │ 資産返却、退職NDA│
                                                    └──────────────────┘
```

| ライフサイクル | 主な管理策 | 監査での確認ポイント・引っかけ |
| :--- | :--- | :--- |
| **雇用前** | ・身元確認、経歴審査（法的許容範囲内）<br>・セキュリティ条件を明記した雇用契約の締結 | 派遣や業務委託者についても、正社員と同等のセキュリティ契約・誓約が結ばれているか。 |
| **在職中** | ・定期的（年1回以上）なセキュリティ教育・標的型攻撃メール訓練<br>・利用規程（AUP）の遵守誓約、懲戒手続 | ・受講履歴・出席簿（未受講者への再教育措置）<br>・違反時の懲戒規定が就業規則等に明文化されているか。 |
| **退職・異動時** | ・職務変更・退職日当日のアクセス権変更・削除<br>・PC、IDカード、鍵等の貸与資産の即時返却<br>・退職後の守秘義務誓約の再確認 | **【最頻出】** アカウント削除漏れの有無。人事マスタの退職者リストとAD等のアクティブアカウントを突合して監査する。 |

## 3. 物理的管理策（Physical Controls）

オフィス、サーバルーム、データセンター、執務室、媒体（USB・ハードディスク）などの物理的保護です。監査では**現地往査（オンサイト観察）**が威力を発揮します。

| 管理策領域 | 具体的な対策内容 | 監査での確認ポイント（実地観察項目） |
| :--- | :--- | :--- |
| **物理的境界** | 執務エリア、重要機器室（サーバルーム）、受付エリアをゾーン分けし、境界を設ける。 | ・入退室ゲート、フラッパーゲートの設置<br>・外部来訪者がフリーに入れる領域の制限 |
| **入退室管理** | ICカード、生体認証、監視カメラ（CCTV）による入退室記録と共連れ（テールゲーティング）防止。 | ・入退室ログと入退出記録簿の突合<br>・来訪者用バッジの着用、常時同行ルールの遵守 |
| **クリアデスク・クリアスクリーン** | 離席時のPC画面ロック、机上やプリンタへの機密文書放置の禁止。 | ・無人PCのスクリーンロック（自動ロック設定時間）<br>・ホワイトボードの消し忘れ、複合機の取り忘れ文書 |
| **機器・媒体の保全と安全な廃棄** | 重要機器の電源冗長化（UPS）、空調設備。記憶媒体（SSD・HDD・磁気テープ）の物理破壊または消去。 | ・定期点検記録（UPS、消火設備）<br>・廃棄業者の物理破壊証明書、データ消去証明書 |

## 4. 技術的管理策（Technological Controls）

システム、ネットワーク、アプリケーション、データそのものに対する論理的セキュリティ対策です。監査では主に**情報システム部・インフラ運用・開発部門**がヒアリング対象となります。

| 管理策領域 | 具体的な対策内容 | 監査での確認ポイント・技術的証拠 |
| :--- | :--- | :--- |
| **アクセス制御と認証** | ・最小権限の原則（Need to Know）<br>・多要素認証（MFA）の適用<br>・特権ID（Administrator / root）の厳格管理 | ・特権ID利用時の事前申請・承認記録<br>・特権IDの共有利用禁止（個人識別可能な運用）<br>・定期的なアクセス権棚卸記録（休眠IDの停止） |
| **暗号化と鍵管理** | ・通信経路の暗号化（TLS等）<br>・保存データの暗号化（ストレージ暗号化、DB暗号化）<br>・暗号鍵のライフサイクル管理（生成・配布・保管・破棄） | ・暗号化アルゴリズムが推奨規格（レガシーでないか）<br>・暗号鍵がデータと同一場所に平文保管されていないか |
| **ログ取得と監視** | ・監査ログ、認証ログ、管理者操作ログの取得<br>・ログ保管期間の遵守と改ざん防止（WORM等）<br>・NTPによる正確な時刻同期（タイムスタンプ） | ・システム時刻がNTPサーバと同期しているか<br>・ログへのアクセス権が管理者を含め制限されているか<br>・定期的なログレビューやアラート監視体制 |
| **マルウェア対策・脆弱性管理** | ・EDR / アンチウイルスソフトの全端末導入と最新化<br>・定期的なパッチ適用（OS・MW）、脆弱性スキャン | ・パッチ適用ルールの策定（緊急パッチの適用期限）<br>・端末の定義ファイル更新状況のダッシュボード |
| **セキュア開発とデータ保護** | ・開発・テスト・本番環境の分離<br>・テスト環境での本番機密データのマスキング（仮名化）<br>・セキュアコーディング規約、ソースコード診断 | ・開発環境から本番環境へのアクセス遮断<br>・テストデータ作成時のマスキング実施記録<br>・脆弱性診断の受診結果と是正報告 |

## 5. 試験対策：主要管理策の横断的引っかけパターン

1. **特権IDの管理**
   * *誤答例:* 「管理業務の効率化のため、複数名のインフラ担当者で同一の共有管理者アカウント（admin）をパスワード共有して利用した」 → **×（個人の識別・追跡が不可能になるため不適合）**
2. **退職者のアカウント処理**
   * *誤答例:* 「退職予定者から業務引き継ぎの要望があったため、退職後1ヶ月間は社内システムへリモートアクセスできるようアカウントを維持した」 → **×（退職日または権限終了日までに即時停止・削除しなければならない）**
3. **テストデータのマスキング**
   * *誤答例:* 「リアルなバグを発見するため、本番環境の個人情報を含む顧客データベースをそのままコピーして開発環境に展開した」 → **×（テスト環境は本番よりセキュリティが緩いことが多く、マスキングやダミーデータ化が必須）**
4. **代替統制（基本項目と詳細項目）**
   * *誤答例:* 「サーバルームに入退室管理ゲートが設置されていないため、常時警備員が同席し台帳管理を行っている場合でも、直ちに管理目標未達とする」 → **×（基本項目の管理目標が同等以上の有効性で達成されていれば代替統制として認められる）**
