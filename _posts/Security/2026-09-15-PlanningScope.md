## 1. 監査計画フェーズの全体像と位置づけ

情報セキュリティ監査基準（実施基準）において、監査計画の策定は監査業務の成否を左右する中核プロセスです。監査人は、被監査主体の状況やリスクを的確に把握した上で、適切な監査資源を配分し、実行可能な計画を立案しなければなりません。

```
【監査プロセスの全体フローと計画フェーズ】
┌─────────────────────────────────────────────────────────────┐
│ ① 監査計画フェーズ (本資料の対象)                          │
│    ・予備調査・事前情報収集                                 │
│    ・監査対象・スコープの画定                               │
│    ・監査リスクの評価と重要性の基準値設定                   │
│    ・年間基本監査計画書 / 個別監査計画書の策定              │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ ② 監査実施フェーズ (往査・証拠収集)                         │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ ③ 監査報告フェーズ (意見表明・助言・フォローアップ)         │
└─────────────────────────────────────────────────────────────┘
```

## 2. 監査対象・スコープの画定（境界線の引き方）

監査スコープ（監査範囲）を明確に定義することは、監査人と被監査主体との認識の齟齬を防ぎ、監査責任の範囲を確定させるために不可欠です。

### (1) スコープ画定の4つの軸（境界線の要素）

| 分類軸 | 画定の視点 | 境界線の具体例・着眼点 |
| :--- | :--- | :--- |
| **① 組織的範囲** | どの組織単位を対象とするか | 全社、特定事業本部、特定子会社、海外拠点、特定の業務委託先など。 |
| **② 物理的範囲** | どの拠点を対象とするか | 本社ビル、支社、データセンター、サテライトオフィス、テレワーク環境など。 |
| **③ 論理的・システム的範囲** | どのシステム・ネットワークを対象とするか | 基幹業務システム、クラウドサービス（IaaS/SaaS）、社内LAN、DMZ、開発環境など。 |
| **④ 業務・プロセス的範囲** | どの業務プロセスを対象とするか | 顧客情報取扱業務、ECサイト運営業務、システム運用保守業務など。 |

### (2) スコープ設定における実務上の留意点
1. **境界線の曖昧さの排除:**
   * 共有インフラ（全社共通Active Directory、共通ネットワーク等）や外部委託先との接続点は責任分界が曖昧になりやすいため、スコープ内か除外かを明確に線引きする。
2. **スコープ除外事項の明記:**
   * 監査対象外とする領域（例：「基幹DBは対象とするが、連携する外部SaaSの基盤内部は除外」など）がある場合、その理由とともに計画書および報告書に明示する。
3. **言明（アサーション）との整合:**
   * 被監査主体が責任を負い、言明を行える範囲と監査スコープが一致していなければならない。

## 3. 年間基本監査計画書と個別監査計画書の記載要件と違い

監査計画は、中長期・組織全体を俯瞰する**「基本監査計画（年間計画）」**と、各テーマ・各往査ごとに具体化する**「個別監査計画」**の2段階で立案されます。

```
┌─────────────────────────────────────────────────────────────┐
│ 年間基本監査計画書 (Master Audit Plan)                      │
│ ・組織全体の年間（または複数年）の監査方針とスケジュール    │
│ ・監査資源（予算・要員）の配分                              │
└──────────────────────────┬──────────────────────────────────┘
                           │ 個別テーマごとに具体化
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 個別監査計画書 (Individual Audit Plan)                      │
│ ・特定のシステムや部門を対象とした実務計画                  │
│ ・監査手続、日程、チェックリスト、往査スケジュール          │
└─────────────────────────────────────────────────────────────┘
```

### 比較一覧表

| 項目 | 年間基本監査計画書 | 個別監査計画書 |
| :--- | :--- | :--- |
| **策定のタイミング** | 年度開始前（定期的な見直しあり） | 個別の監査業務の実施前 |
| **主たる目的** | 組織全体の監査方針の確立、重点分野の選定、年間リソース配分 | 特定監査業務の円滑・確実な遂行、具体的監査手続の確定 |
| **記載要件（主な内容）** | ・年間監査方針・重点施策<br>・年間監査スケジュール<br>・監査対象組織・システムの選定理由<br>・監査体制・要員計画・年間予算<br>・品質管理方針 | ・当該監査の目的・スコープ<br>・適用する監査基準・管理基準<br>・監査日程（予備調査・往査・報告会）<br>・監査チーム編成と役割分担<br>・監査手続概要（監査手続書）<br>・重要性（マテリアリティ）の基準値<br>・被監査部門への依頼事項（事前提出資料等） |
| **承認者** | 経営陣、取締役会、監査役会など | 監査責任者（リードオーディター）、監査部門長 |

## 4. 試験対策用：重要キーワード・引っかけパターン

1. **スコープの変更手続き**
   * *誤答例*：「予備調査の段階で想定外のリスクが見つかった場合でも、一度確定した個別監査計画のスコープは絶対に修正してはならない」 → **×（合理的な理由がある場合、被監査主体・依頼者と合意の上で計画およびスコープを修正・改訂する）**
2. **基本計画と個別計画の作成順序**
   * *誤答例*：「個別監査計画をすべて策定・完了させた後に、それらを合算して年間基本監査計画書を作成する」 → **×（全体の年間方針やリスク評価に基づいて基本監査計画を立て、それを各業務に展開して個別計画を策定する）**
3. **外部委託領域のスコープ扱い**
   * *誤答例*：「外部委託先は別法人であるため、いかなる場合も情報セキュリティ監査のスコープに含めることはできない」 → **×（委託業務が被監査主体の情報セキュリティに重大な影響を与える場合、委託契約の監査条項に基づきスコープに含める、または第三者認証等の監査証拠を利用する）**
